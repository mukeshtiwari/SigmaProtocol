Library Examples.EncProofIns

Proof that an ElGamal ciphertext encrypts one of a list of messages

A concrete instance of the disjunctive encryption proof of Crypto/EncProof.v: given a ciphertext cp = (c₁, c₂) under public key h and a public list of candidate plaintexts [m₀; m₁; m₂] (group elements), the prover shows that cp encrypts one of them without revealing which. Statement i is the Chaum–Pedersen relation

∃ r, c₁ = g^r ∧ c₂·mᵢ⁻¹ = h^r,
and the proof is their OR-composition in the style of Cramer, Damgård and Schoenmakers (CRYPTO 1994): two branches are simulated with self-chosen challenges, the real one is run with the remaining share of the verifier's challenge. This is the ballot-validity proof of Helios-like systems. The file is extracted to OCaml by src/Extraction/EncProoflib.
The group is the order-q subgroup of Z_p^* for the toy safe prime p = 2q + 1 = 5927 with q = 2963 (from Utility/Zpstar.v: Zp q is the scalar field and Schnorr_group p q the group of quadratic residues mod p). The parameters are far too small to be secure; they are chosen so that primality can be proved by trial division (Examples/Prime.v) and the extracted code runs instantly.
Here g = 12, the public key is h = 25, and the ciphertext cp encrypts m₂ = 38 with randomness r = 1876; the prover knows that it is branch 2 (Fin.FS (Fin.FS Fin.F1)). The transcript has three commitments (pairs of group elements), four challenges and three responses.

  Proof.

     (@mul_schnorr_group p q prime_p prime_q m₂
     (@pow _ _ _ safe_prime prime_p prime_q h r))).
  Defined.

The three commitments, each a pair: (g^u, h^u) for the branch treated as real and a simulated (g^uᵢ·c₁^(-cᵢ), h^uᵢ·(c₂·mᵢ⁻¹)^(-cᵢ)) for the others, computed from uscs (three us followed by the two simulated challenges). The split m = 2, n = 0 places the real branch at position 2 (m₂), the same position the prover below uses (Fin.FS (Fin.FS Fin.F1)). The two must agree: the non-interactive prover hashes these commitments, and with any other split the hashed commitments would differ from the announcement in its transcript, so a verifier could not recompute the Fiat–Shamir challenge. The test src/Executable/EncProofcode/fs_binding_test.ml checks this.
  Definition construct_encryption_proof_elgamal_commitment_ins
    (uscs : Vector.t (@Zp q) 5) :
    Vector.t (@Schnorr_group p q × @Schnorr_group p q) 3.
  Proof.
    refine(@construct_encryption_proof_elgamal_commitment
    (@Zp q) zp_opp (@Schnorr_group p q)
    (@inv_schnorr_group 2 p q safe_prime prime_p prime_q)
    (@mul_schnorr_group p q prime_p prime_q)
    pow 2 0 (uscs) [m₀; m₁; m₂] g h cp).
    eapply prime_q.
    exact safe_prime.
    eapply prime_p.
    eapply prime_q.
  Defined.

The full proof for the verifier's challenge c, with real branch 2 and witness r.
  Definition generalised_construct_encryption_proof_elgamal_real_ins

      Zpfield.zero zp_add zp_mul zp_sub zp_opp (@Schnorr_group p q)
      (@inv_schnorr_group 2 p q safe_prime prime_p prime_q)
      (@mul_schnorr_group p q prime_p prime_q)
      pow 1 (Fin.FS (Fin.FS Fin.F1)) r (uscs)
      [m₀; m₁; m₂] g h cp c).
    eapply prime_q.
    eapply prime_q.
    exact safe_prime.
    eapply prime_p.
    eapply prime_q.
  Defined.

The non-interactive proof: c is fn applied to p, q, g, h, the candidates, the ciphertext and the commitments; fn is a hash function supplied by the OCaml caller (strong Fiat–Shamir).
  Definition nizk_generalised_construct_encryption_proof_elgamal_real_ins
    (fn : ∀ {m : nat}, Vector.t (Z + ((@Schnorr_group p q) +
      (@Schnorr_group p q × @Schnorr_group p q))) m → (@Zp q))
    (uscs : Vector.t (@Zp q) 5) :
    @sigma_proto (@Zp q) (@Schnorr_group p q × @Schnorr_group p q) 3 4 3.
  Proof.
    set (comm := construct_encryption_proof_elgamal_commitment_ins uscs).
    set (c := fn _ ([inl p; inl q; inr (inl g); inr (inl h);
      inr (inl m₀); inr (inl m₁); inr (inl m₂)] ++
      Vector.map (fun x ⇒ inr (inr x)) (cp :: comm))).
    refine(generalised_construct_encryption_proof_elgamal_real_ins uscs c).
  Defined.

The verifier: the sub-challenges sum to the main challenge and each branch is an accepting Chaum–Pedersen transcript for (g, h) and (c₁, c₂·mᵢ⁻¹).
  Definition generalised_accepting_encryption_proof_elgamal_ins
    (proof : @sigma_proto (@Zp q) (@Schnorr_group p q × @Schnorr_group p q) 3 4 3) : bool.
  Proof.
    refine(@generalised_accepting_encryption_proof_elgamal
      (@Zp q) Zpfield.zero zp_add zp_dec
      (@Schnorr_group p q)
      (@inv_schnorr_group 2 p q safe_prime prime_p prime_q)
      (@mul_schnorr_group p q prime_p prime_q) pow
      Schnorr.dec_zpstar _ [m₀; m₁; m₂] g h cp proof).
    eapply prime_q.
    exact safe_prime.
    eapply prime_p.
    eapply prime_q.
  Defined.
