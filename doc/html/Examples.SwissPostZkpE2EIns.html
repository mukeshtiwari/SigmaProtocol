Library Examples.SwissPostZkpE2EIns

Swiss Post zero-knowledge proofs at the Post_E2E_DEV group

The verifiers of the zero-knowledge proofs of the Swiss Post crypto-primitives library (specification 1.6.0, section 10: Schnorr, decryption, exponentiation and plaintext-equality proofs) at the group of BayerGrothE2EIns.v (the 3072-bit encryption group of the Swiss Post synthetic election Post_E2E_DEV, g = 2), whose prime_q is an axiom, not a certificate.
Each proof is a Maurer-style proof of a preimage for a group homomorphism φ : Z_q^K → G^m whose components are multi-exponentiations, φ(w)ᵢ = ∏ⱼ B_(i,j)^wⱼ, for a public statement y ∈ G^m. The proof is published in compact form (e, z): the verifier reconstructs the announcement c'ᵢ = yᵢ^(-e) · ∏ⱼ B_(i,j)^zⱼ and checks e = H(c'), where H is the specification's RecursiveHash with the public values (the statement and auxiliary data) fixed. This is verify_rows of Backend/BBSSharpVerifier.v, whose reconstruction (ext_reconstruct, Crypto/OkamotoRows.v) uses the same sign convention y^(-e).
The matrix of bases B for each proof is built by the OCaml driver Executable/Swisspostzkp (and is trusted):
  • Schnorr: K = 1, m = 1, row [g], statement y.
  • Exponentiation: K = 1, m = n, rows [gᵢ], statements yᵢ.
  • Plaintext equality: K = 2, m = 3, rows [g, 1], [1, g], [h, h'⁻¹], statement (c₀, c'₀, c₁/c'₁).
  • Decryption: K = ℓ, m = 2ℓ, rows g·eᵢ and γ·eᵢ (with eᵢ the i-th unit vector), statements pkᵢ and φᵢ/mᵢ.
The generalised Okamoto protocol of Crypto/Okamoto.v needs at least two bases per row, so verify_rows_accepting is stated for K ≥ 2. To cover K = 1 as well, verify_zkp_ins appends a column of base 1 with response 0; this changes neither φ nor the reconstruction, and every proof gets the accepting-transcript theorem verify_zkp_ins_accepting.
