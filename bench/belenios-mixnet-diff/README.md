# Differential testing of the Belenios mix-net

Compares the shuffle verifier of Belenios, `check_shuffle_proof` in
[mixnet.ml](../belenios-diff/_work/belenios/src/lib/v1/mixnet.ml) (Belenios
3.2.0), with the prime-order model of this repository's certified mix-net
verifier ([VerificatumVerifier.v](/src/Backend/VerificatumVerifier.v) over
[ShuffleTW.v](/src/Crypto/ShuffleTW.v)), on a non-homomorphic (mix-net)
Belenios election. Both implement the same Terelius–Wikström proof of a
shuffle. The finding is in [FINDINGS.md](FINDINGS.md).

Belenios's mix-net is a different question type from the homomorphic
elections exercised by [`bench/belenios-diff`](../belenios-diff); the
certified Belenios verifier of this repository only reads homomorphic
questions, so there is no certified verifier that reads a Belenios shuffle
archive directly. The comparison here is therefore at the level of the
algorithm: an independent Python port of `check_shuffle_proof`
([mix_lib.py](mix_lib.py)) that agrees with `belenios-tool` on every honest
shuffle, and the prime-order group over which the certified
Terelius–Wikström verifier is defined and proved sound.

## Reproducing

```sh
bench/belenios-diff/run.sh            # builds belenios-tool 3.2.0 (once)
bench/belenios-mixnet-diff/run.sh     # SEEDS=100 JOBS=4 by default
```

`run.sh` runs [campaign.py](campaign.py) (the single-shuffle torsion
comparison) and then [campaign_ext.py](campaign_ext.py) (the extended stages
below: chains of mix servers, multiple tainted outputs, the joint-decryption
control). `EXT_SEEDS=n` sets the seeds per configuration of the extended
stages (default 50).

`run.sh` reuses the `belenios-tool` built by `bench/belenios-diff/run.sh`
(same pinned commit `50a79aed…`, tag 3.2.0) and runs
[campaign.py](campaign.py) on the committed fixture. `run.sh --regen`
regenerates the fixture with [gen_mix.sh](gen_mix.sh) (a different archive,
the same kind of election; `belenios-tool` reads `/dev/urandom`). The
campaign is otherwise deterministic: every case is seeded. Results are
written to [results/](results): `honest.tsv` and `torsion.tsv`.
Requirements: python3 (no packages), jq, and the `bench/belenios-diff`
build. Run time: about 20 s at 100 seeds on an Apple M3 Pro.

The fixture is a non-homomorphic election generated by `belenios-tool`
3.2.0 following Belenios's `tests/tool/demo-nh.sh`: Ed25519, two "Single"
trustees, one homomorphic and one `NonHomomorphic` question, three ballots,
two shuffles (trustees 1 and 2), decryption and result.

## The cases

- **honest**: the two shuffles of the fixture, re-checked by the Python port
  of `check_shuffle_proof`. The port and `belenios-tool` accept both, and
  every output ciphertext is a prime-order subgroup element. This is the
  fidelity check of the port.
- **torsion**: a mix server's output carries a low-order point. Output #0's
  `beta` is replaced by `beta + T` with `T` of order 2 or 8, so the output
  is not in the prime-order subgroup, and a fresh shuffle proof is produced
  for that output with the Python prover. Each case is a one-shuffle archive
  fed to `belenios-tool election verify`, over 100 seeds per order.

## Results (SEEDS=100)

| order of T | cases | outputs out of subgroup | belenios-tool accepts | certified model |
|---|---|---|---|---|
| 2 | 100 | 100 | 26 | rejects all |
| 8 | 100 | 100 | 2 | rejects all |

`belenios-tool election verify` reports "all checks passed" on a shuffle
whose output ciphertext is not a prime-order subgroup element, for a
fraction of seeds that depends on a Fiat–Shamir challenge (higher for the
order-2 point). The certified Terelius–Wikström verifier is defined over a
prime-order group in which such a point does not exist, and its drivers
reject any point not of order *l* at parse time, so this repository's
certified pipeline rejects every one of these outputs. See
[FINDINGS.md](FINDINGS.md) for the cause and the scope.

## Extended campaign ([campaign_ext.py](campaign_ext.py), EXT_SEEDS=50)

**chain** — a chain of *N* mix servers, one of which (at position *t*, counted
from the input) taints its output #0 with an order-2 point; the others are
honest. The tampered output always reaches the end of the chain outside the
subgroup (250/250 cases), because an honest re-encryption `(g^r, pk^r)·c`
preserves a torsion component rather than removing it. The whole chain's
shuffle check is still accepted for a fraction that *falls the earlier the
taint is injected*, since every shuffle downstream of the taint must then also
pass its own check with a torsion-carrying input:

| mixers *N* | taint at *t* | belenios-tool accepts the chain |
|---|---|---|
| 2 | 0 | 4/50 |
| 2 | 1 (last) | 12/50 |
| 3 | 0 | 0/50 |
| 3 | 1 | 2/50 |
| 3 | 2 (last) | 16/50 |

A malicious **last** mixer has the best odds (only its own proof sees the
torsion), close to the single-shuffle rate.

**multi** — a single shuffle taints *j* of the *M* = 3 outputs:

| order of T | j = 1 | j = 2 | j = 3 |
|---|---|---|---|
| 2 | 12/50 | 10/50 | 11/50 |
| 8 | 2/50 | 0/50 | 0/50 |

For an order-2 point the acceptance rate is *flat* in *j*: the order-2
contributions of all tainted outputs collapse into a single parity bit of the
challenge, so tainting more outputs is no harder. An order-8 point gives a
stricter (mod-8) condition that compounds and quickly vanishes.

**rocq** — the same Belenios shuffles run through the *extracted* certified
Terelius–Wikström verifier (`Crypto/ShuffleTW.v`'s `tw_verify`) at Ed25519, via
the driver [Executable/Belenioshuffleverifier](/src/Executable/Belenioshuffleverifier/main.ml).
It accepts belenios-tool's honest shuffles (cross-validating the two
implementations) and shows that the guarantee against torsion lives in the
certified driver's parse-time subgroup check, not in the algebra. See
[ROCQ.md](ROCQ.md); results in [results/rocq.tsv](results).

**decrypt** (control) — adding an order-2 point to a published decryption
factor, or to a ciphertext of the encrypted tally, is rejected by
`belenios-tool` in both cases. The joint-decryption path subgroup-checks what
it consumes (`check_factor`'s `G.check f`, `check_result`'s `check_ciphertext`
in [election.ml](../belenios-diff/_work/belenios/src/lib/v1/election.ml)); the
contrast localises the gap to `check_shuffle_proof`. Results in
[results/chain.tsv](results), [results/multi.tsv](results),
[results/decrypt.tsv](results).
